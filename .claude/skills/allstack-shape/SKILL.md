# Shape the job

Work inside the current coding host. This skill needs no delivery run, task creation, commit, or publication authority. Repository policy still applies. Read the user's request and relevant source before proposing changes.

## Establish demand and boundaries

Name who encounters the problem, what they do today, and the cost of that behavior. Separate observed demand from assumptions. For an internal tool, inspect the actual current workflow or inputs instead of inventing market validation. Use Allstack recall or available Prime tools for relevant prior decisions; open their sources before adopting them.

State one complete job a human can finish when this change works. Make its trigger, inputs, output, and failure behavior concrete. Distinguish the requested outcome from a suggested implementation. Ask only for missing information that could change the product decision; continue independent investigation while waiting.

## Challenge the proposed scope

- Compare extending the current path, using an existing tool, and building a new path when those alternatives are credible. Explain integration and maintenance consequences using inspected evidence.
- Identify the narrow user-facing result that solves the problem completely. Name work that contributes no observable result and remove it from the proposal.
- Test the most consequential assumption: missing access, unclear data ownership, deployment constraints, or an unobserved demand claim. Choose an executable probe or ask for the necessary decision.
- Preserve the user's direction. Model agreement and recalled notes do not authorize a different product, external write, or new repository.

## Deliver a decision-ready brief

Describe the user problem, current evidence, alternatives, recommendation, complete flow, unresolved decisions, and observable acceptance. Use rock/sand/water confidence when uncertainty matters; do not invent time estimates.

For an implementation handoff, save under the repository's indexed docs layout. With applicable local-write authority, use `allstack remember --kind decision --source <indexed-doc> --summary <accepted-decision>` only after a decision is accepted. Label proposals as proposals. Memory is context, never permission. Stop after shaping unless implementation was requested.

## Host capability

Claude Code: invoke as /allstack-<name> or request its name naturally. Use native repository tools and its current permission mode. An unavailable or denied tool leaves its check unverified.
