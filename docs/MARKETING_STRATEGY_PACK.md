# AllSource marketing strategy pack

Status: active

Source of truth: [BET.md](./BET.md). If this pack conflicts with the bet,
`BET.md` wins.

## Research principles applied

- Prove retained hosted revenue before building affiliate infrastructure.
- Use open source and free technical proof to identify hosted intent.
- Enter exact developer communities with native evidence, not launch spam.
- Turn reproducible benchmarks and real workflows into search- and AI-citable
  assets.
- Use trusted technical creators after they can demonstrate product honestly.
- Treat third-party traffic and affiliate platforms as volatile dependencies;
  keep repository, docs, email audience, and customer evidence owned.

## Objective

Produce qualifying hosted customers who complete a real agent-memory circuit,
pay for AllSource, and remain paid through first renewal. Marketing must move a
technical buyer from one concrete failure—lost or untraceable agent state—to a
restart and provenance proof using their own workload.

GitHub stars, impressions, citations, benchmark views, newsletter opens,
self-host installs, signups, and trial starts remain diagnostic. None satisfies
the promotion gate.

## Positioning kit

- Audience: technical founders and small teams running stateful AI agents.
- Trigger: useful agent state disappears after restart or cannot be traced to
  its source.
- Problem: current-state memory cannot reconstruct what the agent knew, when it
  knew it, or why.
- Promise: store agent activity as durable ordered events, then recall, replay,
  inspect past state, and follow provenance after restart.
- Proof mechanism: real-workload restart demonstration with visible source
  events and reproducible benchmark methodology.
- Primary CTA: `Run the restart proof`.
- Paid CTA: `Start hosted AllSource — 14-day trial, then from £18.99/month`.
- Trust line: `Self-host under Apache-2.0. Hosted prices come from the live GBP catalog.`

Avoid “perfect memory,” “revolutionary,” “seamless,” and blanket claims about
competitors. Lead with buyer failure and proof. Architecture, tool count, and
benchmarks support the claim; they are not the headline.

## Revenue system

### Core revenue

- Recurring hosted subscriptions through LemonSqueezy.
- Indie is default first purchase; live workload determines upgrades to Studio
  or Scale.
- Annual billing may improve cash flow only after monthly activation and
  retention are measured.
- Enterprise remains sales-led and outside first promotion gate.
- Report net revenue after refunds, chargebacks, taxes, LemonSqueezy fees,
  infrastructure cost, support cost, and partner commission.

### Open-source conversion route

Open source proves substrate and earns technical trust. Each repository and
installation route should make next step explicit:

1. Run one-command self-host installation.
2. Complete same restart and provenance proof used by hosted product.
3. Show operational work customer owns when self-hosting.
4. Offer hosted trial for buyers who want AllSource to operate that work.

Do not cripple self-hosting to manufacture conversion. Hosted value is managed
operation, provisioning, access control, quotas, billing, and support.

### Free intent diagnostic

Available free technical evidence is open-source code plus reproducible
benchmark methodology. Primary free product proof to publish is the restart and
provenance demonstration. Planned `memcheck` remains a draft and must not be
promoted as available.

If `memcheck` ships, it should:

1. Ask which memory stack and workload shape buyer uses.
2. Identify whether restart survival, temporal inspection, or provenance is
   missing;
3. show sourced comparisons and explicit assumptions;
4. keep inputs in browser; and
5. route qualified buyer to self-host proof or hosted trial.

It must not invent competitor figures, upload private agent data, or recreate
full hosted value for free.

### Expansion after promotion

Consider only after promotion gate passes:

- annual hosted plans for activated customers;
- paid implementation review with fixed scope;
- framework-specific integration packs backed by repeated demand;
- creator and consultant referrals selling hosted AllSource;
- enterprise security, compliance, and deployment work after requirements and
  margins are known.

Do not add unrelated database, token, x402, or generic AI offers to first paid
journey.

## Commercial search coverage system

Ward-derived rule: map commercially relevant demand before producing more
content; build owned surfaces nearest revenue; influence sources already cited
in buyer decisions; measure coverage across Google, AI answers, and those
sources. Sources: [organic search system](https://www.linkedin.com/pulse/seo-2026-playbook-winning-google-ai-search-everywhere-jake-ward-jjfbe),
[structured programmatic pages](https://www.linkedin.com/pulse/programmatic-seo-2026-how-i-built-13000-pages-3-hours-jake-ward-pcjke),
and [native authority content](https://www.linkedin.com/pulse/why-you-should-publishing-articles-linkedin-xtwitter-right-jake-ward-3aome).

- Buyer-near query set: durable AI-agent memory; agent memory after restart;
  memory with provenance; replay AI-agent decisions; reconstruct what an agent
  knew; Mem0, Zep, and Letta alternatives; LangGraph, LangChain, LlamaIndex,
  CrewAI, AutoGen, and MCP memory integrations.
- Owned surface order: improve existing comparison and alternative pages;
  publish one framework-plus-failure decision page per distinct intent; connect
  each page to runnable restart proof, documentation, and hosted trial.
- Influenced-source map: for every query cluster, record recurring GitHub
  discussions, framework documentation, MCP directories, technical
  comparisons, Reddit threads, LinkedIn articles, and X discussions; pursue
  factual inclusion or contribute useful implementation evidence.
- Native authority asset: publish one original restart, correction-history, or
  point-in-time reconstruction experiment; site holds reproducible artifact,
  while LinkedIn and X receive distinct native explanations.
- Working utility: ship `memcheck` only when it performs real local diagnosis
  and links each result to evidence; never publish a text-only tool shell.
- Rollout rule: release five to ten structured pages, validate uniqueness,
  indexation, proof use, and qualified trial progression, then keep, revise, or
  stop. Never copy Ward's page volume without matching structured data.
- Coverage metric: percentage of mapped buyer queries with correct owned page,
  percentage with truthful AllSource presence in recurring cited sources, and
  qualified restart-proof progression by cluster. Coverage remains diagnostic;
  retained hosted customers remain promotion gate.

## Content engine

Every content unit starts with one real failure, one reproducible proof, and one
bounded claim.

### Pillars

1. Restart survival: event ingest, process restart, recall, and recovered source
   events.
2. Provenance: how to answer “why does the agent believe this?” without exposing
   private payloads.
3. Temporal debugging: reconstruct agent state at a past moment and replay change.
4. Architecture: WAL, Parquet, projections, and division between Core events and
   operational metadata.
5. Performance: reproducible workload, hardware, configuration, limitations, and
   result—not isolated headline number.
6. Adoption: API, SDK, and MCP recipes tied to one real framework workflow.
7. Honest comparisons: capability, operating burden, price basis, source date,
   and primary-source citation.

### Repurposing circuit

One strong restart proof becomes:

- runnable repository example;
- technical guide with commands and expected output;
- short screen recording;
- benchmark or architecture card;
- native community explanation;
- newsletter issue or founder thread;
- factual answer page suitable for search and AI citation;
- onboarding step inside hosted product.

Keep canonical facts in one source. Update derived copy after benchmark, pricing,
license, tool-count, or product-limit changes.

### Search, GEO, and AEO rules

- Use one answerable question per page and answer it near top.
- Name AllSource, category, supported workflow, limits, and current source date.
- Cite primary documentation, benchmark method, pricing catalog, and repository.
- Publish author, organisation, contact, canonical URL, update date, and relevant
  structured data.
- Make important facts available in server-rendered HTML without interaction.
- Link each claim to proof and each proof to installation or hosted trial.
- Avoid scaled near-duplicate comparison and framework pages.
- Measure search traffic, AI referrals, cited landing pages, proof completion,
  and retained revenue together. Citation alone is not success.

## Affiliate and partner policy

### Before gate

- No public affiliate programme or affiliate platform work.
- Track introductions using UTM source, medium, campaign, content, and a separate
  partner identifier.
- Reconcile any founder-approved referral manually against trusted
  LemonSqueezy subscription and refund state.
- Never put tenant IDs, emails, API keys, prompts, or event payloads in URLs.

### After gate candidate

- Partner: agent-framework educator, AI infrastructure consultant, technical
  newsletter, MCP integrator, or developer creator.
- Product promoted: hosted AllSource subscription only.
- Candidate commission: 20% of net subscription revenue for first 12 paid
  customer months, subject to margin review and founder approval.
- Payout trigger: settled invoice outside applicable refund and chargeback
  window.
- Reversal: refund, chargeback, fraud, self-referral, duplicate attribution,
  trademark bidding, spam, or prohibited promotion.
- Disclosure: partner identifies commercial relationship before engagement.
- Attribution: last eligible partner touch before trial, with direct and
  customer-declared corrections reviewed manually.

Do not promise lifetime commission, exclusivity, paid placement disguised as
editorial, or commission on self-host use.

## Autoresearch protocol

Use fixed evaluator for marketing experiments:

| Criterion | Weight |
| --- | ---: |
| Progress toward qualifying retained-customer gate | 35 |
| Real-workload restart and provenance completion | 20 |
| Claim accuracy, security, and buyer trust | 20 |
| Net revenue and contribution margin | 15 |
| Simplicity and reversibility | 10 |

Loop:

1. Record current audience, page, message, source, and funnel baseline.
2. Change one concept: trigger, proof, offer framing, CTA, channel, or onboarding
   handoff.
3. Keep product limits, billing truth, architecture, security boundary, and bet
   gate unchanged.
4. Compare first-value completion, paid activation, renewal, and net revenue;
   use clicks only to diagnose drop-off.
5. Inspect failed sessions and support categories without collecting private
   event content.
6. Keep clear improvement. Revert regression. Prefer simpler variant on tie.

Never optimize benchmark headline, star count, or signup volume at expense of
qualified retention.

## Measurement contract

### Product and revenue events

- `restart_proof_started`
- `restart_proof_completed`
- `hosted_trial_started`
- `api_key_created`
- `first_real_event_ingested`
- `first_recall_succeeded`
- `first_point_in_time_query_succeeded`
- `first_provenance_viewed`
- `first_replay_completed`
- `checkout_started`
- `subscription_activated`
- `subscription_renewed`
- `subscription_refunded`
- `subscription_cancelled`
- `subscription_chargeback`

Only trusted server and LemonSqueezy evidence may set payment, renewal, refund,
and chargeback events. Browser analytics may describe intent, never revenue truth.

### Required properties

- pseudonymous tenant identifier;
- plan and billing period;
- acquisition source, medium, campaign, and content;
- partner identifier when applicable;
- integration route: API, SDK, MCP, or self-host handoff;
- first-value stage and failure category;
- whether founder help or custom engineering was required; and
- trusted invoice identifier on server-side revenue records.

Exclude raw event payloads, prompts, source documents, API keys, access tokens,
email addresses, and other personal data from product analytics.

Primary metric: qualifying non-founder hosted customers retained through first
renewal.

Supporting metrics:

- qualified visitor to restart-proof start;
- proof start to completion;
- trial start to first real event;
- first real event to first recall and provenance view;
- first value to paid activation;
- paid activation to renewal;
- net revenue and contribution margin by source; and
- custom-engineering rate during onboarding.
