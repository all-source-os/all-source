1. blocking I3 / Decision 4 / Security (flusher bounds refusal): I3 and Decision 4 say the not-yet-durable tail is drained by the flusher within one tick, and Security says 503 lasts until the flusher drains it. No failure branch is stated. On write error, flush_tenant re-pends the batch and returns Err, so events stay non-durable and the tenant stays non-evictable while writes fail. Evidence: apps/core/src/infrastructure/persistence/storage.rs:488-499; design I3 (:218-224), Decision 4 (:87-88), Security (:680-682); test flusher_bounds_refusal (:584-585) covers healthy writes only. Memory stays under budget because charges refuse, so "unbounded" is overstated. The defect is the stated drain guarantee and the 503 duration, which are unstated and untested. Also storage.rs:447 `self.flush_tenant(&tenant)?` aborts the pass for later tenants (not verified beyond grep). Fix: make I3's bound conditional on flush health. Add flush failure to I3's refusal causes, with its alarm metric and 503 consequence. Add an acceptance test with injected write failure asserting refusal, alarm and tail size. Or bound the tail independently of the flusher.

Add the query.archive term to the budget section.

4. blocking Decision 6 (design:102-113) / hydration_generation_restart (design:602-603) / I8 (design:264-267): hydration liveness unbounded. Each archive_mutation_guard acquisition bumps the generation (design:104-106), and a hydration spanning a bump restarts. Compaction sweep takes the guard once per tenant, including no-op tenants, so a sweep over ~200k tenants bumps many times. No restart cap, backoff, or sweep-pause rule. Test asserts restart only. Bounded in practice by sweep window (interval 3600 s, deadline 240 s), but cold-read bound (design:269-270, Acceptance 5) cannot be met inside a sweep window under the decided rule. Evidence: compaction.rs:647 (sweep calls sweep_tenant per tenant); compaction.rs:756 (guard taken before file listing and size check); compaction.rs:749 (240 s default); archive_repack.rs:32-37 (global mutex, one acquisition per tenant). max_pass_seconds default and cold-read timing not verified. Fix: state the restart bound (max restarts, or bump only when a file changes); skip the guard for no-op tenants or pause hydration during a sweep; add a named test that hydration completes within N restarts while a sweep runs over many tenants.

5. should Decision 4 / I8 (eviction keeps tail; loaded state): Decision 4 keeps non-durable events resident after durable eviction but never says the tenant is marked unloaded. Warm fast path checks only is_loaded() and is_complete() (store.rs:1875-1877, no generation check). If the flag stays set, the next read serves tail-only data, breaking I8 ("a read sees all resident events, or retries"). Today eviction calls mark_unloaded (store.rs:2167, :2197). Design has no mention of unload or the loaded flag for partial eviction (grep "unload": 0 hits). Decision 5 "Warm queries take no gate" is ambiguous on generation checks. Evidence: design:85-92; evict_keeps_tail (design:577-579) asserts full set and no duplicates, not fast-path bypass. Fix: state that eviction always clears the loaded flag, including when a tail remains, and the next read rehydrates and merges the tail. Add to evict_keeps_tail: after partial eviction, the next read takes the cold path and returns the full set.
