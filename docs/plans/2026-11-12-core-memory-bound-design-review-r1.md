2. blocking S1 Reclaim (steps 1-3): reclaim runs inside charge points that already hold parking_lot locks, then takes the same locks again. Non-reentrant RwLock self-deadlocks. Evidence: store.rs:970 (ingest_batch holds `cache_residency_gate.read()`), :999 (`events.write()`), :1030 (push); store.rs:1949 (hydration gate.read()), :2260 (`events.write()` in append_loaded_event), :2290 (charge); try_evict_tenant store.rs:2127-2128 takes gate.write(), then :2154 events.write(); RwLock is parking_lot (store.rs:37). Fix: reserve bytes before taking gate or events locks, or make reclaim a request run after guards drop. Add a test where the failing charge happens under gate.read() plus events.write(). The design's "held storage lock" test does not cover this path.

3. blocking S1 Reclaim step 2: reclaim flushes a pending tenant with a 10 s deadline. That is disk I/O under the gate and events locks, and a synchronous flush cannot be interrupted at 10 s. Evidence: store.rs:2136-2141 comment ("Never perform or wait for disk I/O under the exclusive cache gate. A pending or in-flight flush means memory still owns queryable data") and `storage.try_write()`; design S1 step 2. Fix: flush before the charge path, outside all guards (a background flush that ingest waits on, or refuse at charge time). Reclaim evicts only already-durable data. Drop "flush inside reclaim" or rewrite it as a pre-charge step.

Evidence: main.rs:223-257 (compaction loop); compaction.rs:215 and :571 (auto_compact default true); compaction.rs:1137 (snapshot write), :1149-1160 (constituent removal); store.rs:1405-1447 (compact_entity_tokens; reached from embedded/core.rs:363). Design has no mention of compaction. Fix: key segments by a stable segment id that compaction maps forward, or re-resolve through the narrow index on miss. Define compact_entity_tokens for segment-backed residency. Specify the Tail locator rewrite on flush.
