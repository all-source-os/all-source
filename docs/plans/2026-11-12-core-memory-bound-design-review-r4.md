2. blocking S1 Followers (design:420-427, :422-423; I3 design:223-224; test design:780): The design says a refused WAL-path ingest_replicated returns an error that makes the receiver retry the same offset, and that replication stalls. Code does not do that. wal_receiver.rs:539-547 logs, then returns Ok(()) without ACK. The loop continues (:340-342), the next entry is applied, and last_replayed_offset advances (:550). On reconnect the refused offset is skipped (:522-523). The event is dropped in memory and never replayed, and no stall occurs. A retry would also re-append to the local WAL (:532) and duplicate on recovery (store.rs:469-496). Evidence: wal_receiver.rs:294, :340-342, :463-467, :522-523, :532, :539-547, :550, :564; design:224, :422-425, :780. Fix: on refusal, do not advance last_replayed_offset or ACK, and end the connection with Err so reconnect resumes from the last ACK. Apply the same change to the snapshot path (:463-467). Place the local WAL append after successful ingest, or dedupe on recovery. Correct "retries the same offset" and "stalls". Add a test: refusal, budget frees, event present exactly once.

6. blocking Harness > Replay driver (design:507-508, :515-517, :524-525; flusher :406-409): Baseline and candidates share the fixture volume. Each process ingests 12 seeded events and flushes.
