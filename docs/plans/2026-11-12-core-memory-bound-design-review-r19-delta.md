2. should Decision 1 Broadcast rings (design:284) and owner row: the shared-Arc charge rule has three gaps. (a) Receiver dependency: store ring receiver_count()==0 with WS ring >0 leaves the Arc heap charged nowhere, and the search-disabled path (search_api.rs:65-73) has no store receiver. (b) Release at store-ring overwrite (cap 1,024, store.rs:376) frees the charge while the WS ring still holds the Arc; WS tail advances only on stored sends (tokio broadcast.rs:663-674), so up to 1,000 bodies (websocket.rs:24-25) go uncounted. (c) receiver_count() (broadcast.rs:865-868) and send are check-then-act; a receiver dropping between them leaves a charge no overwrite releases. Evidence: store.rs:762,912,1027,1101 send one Arc to both rings; event_search.rs:149; websocket.rs:88-90. Fix: charge on the Ok(n) result of send, not on a prior receiver_count check; state which ring is charged for a shared Arc, or charge on creation and release on last Arc drop; name the search-disabled case; add negative controls for WS-only and intermittent-WS.

6. should Decision 1 Maps and vectors (design:87-89): "re-read when an insert grows the map" misses pushes into an existing key's Vec. Index entries are Vec<IndexEntry> (index.rs:39-42); push on an existing key (index.rs:82-83, :88-89) grows Vec capacity with no map growth, so the owned heap goes stale and ledger_two_sided (design:517, hard gate) can drift. v18 read "re-read when an insert grows them" (maps and vectors), so v19 narrowed the rule. Fix: re-read the owned String and Vec capacity of the touched key on every insert that changes them, or charge the capacity delta at push; keep the map-growth rule for the map's own table; name this path under ledger_owns_heap (named at design:613, not defined in text).

9. should Harness Determinism (design:415-420), replay set (design:404-411), query_digest (design:457-459): "Requests are never digested.
