1. blocking Decision 5 evictor, abandon_evict (design:188-194; acceptance pin_during_drop design:899-901): abandon_evict sets the loaded flag unconditionally, but begin_evict captures only the integrity bit and last_used. A tenant that was flag-false at begin_evict (a partial tenant after a failed cold load, or a kept-tail tenant after mark_evicted) is marked loaded when the evictor abandons while a cold reader is still splicing. Warm readers with require_complete=false then get a guard over a partial tenant, violating design:205-206 and I8 (design:446-448). Evidence: design:188 (begin_evict captures integrity and last_used, then clears the loaded flag); design:191-192 ("sets the loaded flag again"); design:956-959 (acceptance restores the loaded flag); design:121-126 (pins checked at selection only, no flag filter); store.rs:1982-1984 (load_result? returns early with no rollback; mark_loaded only after splices); store.rs:1869-1876 (warm fast path is is_loaded() && (!require_complete || is_complete()), takes no gate); tenant_loader.rs:153-154 (is_loaded is contains_key). pin_during_drop asserts only that the integrity bit is unchanged, so it passes with the flag wrong. Fix: begin_evict captures the loaded flag; abandon_evict restores the captured value, not true; define restore_after_abandon when the integrity entry is absent (a bool cannot represent absent). Add acceptance: abandon on a flag-false tenant with a cold reader in flight leaves loaded=false, and a warm reader then takes the cold path.

2. blocking Decision 5 "Other readers of events" (design:207-215): the exemption reasons are false. events_after_offset has no replication caller. Its callers are consumer poll (api.rs:2239), websocket replay (infrastructure/web/websocket.rs:145) and search rescan (infrastructure/search/event_search.rs:209). It uses the events-vec index as the consumer cursor (store.rs:1184-1203), and eviction's retain() re-indexes the vec (store.rs:2158, 2171-2178). After an eviction, cursors point at different events, and an evicted tenant's undelivered durable events are never delivered. snapshot_events readers (EventQL api.rs:1835, backup embedded/core.rs:902) return partial data for evicted tenants. Lock exclusion gives snapshot consistency, not completeness. The design states no offset-stability or completeness contract. Also store.rs:1177 documents total_events as "used as max offset for consumer ack"; design:209 and :213-215 do not account for this. Fix: correct each reader's stated reason. Per reader, either pin the tenant set it needs or document partial-data semantics. For events_after_offset, state how offsets stay stable across eviction, or move to durable-stream offsets. Remove "serves replication from offsets" unless a replication caller exists.

3. blocking Decision 5 caller guard lifetime (design:184-186; pins_whole_reads design:950-951) vs the store_feed call site: the design says the caller holds the guard until its read has copied its result. The feed caller discards it. store_feed.rs:490 `self.ensure_tenant_loaded_with_integrity(tenant, true)?;` ends in a statement, so the pin drops at once. Between the is_complete check (:491) and the gate read (:497), an evictor can run (try_evict_tenant takes cache_residency_gate.write() with pin count 0, store.rs:2127-2159, and removes the tenant's feed index at store.rs:2159). The feed then runs on a fresh index and returns an empty page at a fresh epoch with no error, violating I8 ("sees all resident events or retries", design:446-447). Evidence: store_feed.rs:490, :491, :497 (`let _resident = self.cache_residency_gate.read();`, with no re-check of is_complete or the pin). Fix: bind the ResidencyPin through the read at :497 and state it in decision 5, or re-check is_complete under the gate at :497. Add the feed path to pins_whole_reads. The v14 test text would still pass if a caller drops the guard early.

4. blocking Decision 5 "Other readers" list (design:207-215), r13#11 unresolved: the list omits unpinned events readers. Three tenant-scoped routes discard the ensure result (`let _ = self.ensure_tenant_loaded(...)`) and then read events without a pin: list_streams_for_tenant (store.rs:2976-2978), list_event_types_for_tenant (store.rs:3004-3006), stats_for_tenant (store.rs:3040-3042). An eviction between ensure and read returns partial tenant data. A refused or timed-out load (store.rs:1900; ArchiveHydrationRefused) yields an empty list instead of a retry. Other unlisted unpinned readers: reset_projection (store.rs:2335), get_event_by_id (store.rs:2349), stats (store.rs:2912), register_projection_with_backfill (store.rs:1280; exempt only through the "resident set" wording of I7). read_model_journal (store_read_model.rs:254-271) and the store_feed read path (store_feed.rs:497) are gate-protected and should be listed. design:150 "Pins guarantee whole reads" is false for these routes. The design also does not state ensure_tenant_loaded's return type, which decides whether `let _ =` drops a guard. Fix: hold the ResidencyPin across the read in the three routes, with error propagation, or state why partial reads are acceptable and amend I8. Enumerate every events.read/write site outside the pinned query path, with a reason for each. Restate the snapshot_events reason at design:214-215, since lock exclusion is not a whole-tenant guarantee.

5. should Decision 5 entry point (design:168-169, 184-186; acceptance require_complete_respected design:894-895): the text says a require_complete caller "still gets its certification was evicted; retry error when the tenant is loaded but partial". Steps 2-3 (design:174-182) run the cold path for a loaded-but-partial tenant and return a guard. The error is raised by the caller after ensure returns (store_feed.rs:490-495: ensure, then !is_complete raising "feed archive certification was evicted; retry"). Acceptance says the error comes "through the pinned entry". Partial tenants also re-hydrate on every require_complete request (store.rs:1872 requires is_complete; store.rs:1984 leaves complete=false). The design does not state this cost. Fix: say the entry returns a guard and the feed caller raises the error, or return the error at step 2. State the re-hydrate-per-request cost. Align the acceptance test.

6. should Decision 5 cold-path splice restart (design:176-180, 189, 222-223): "a change restarts the load" has no cap and no error. Archive generation has a 3-restart cap that fails with ArchiveHydrationRefused (design:222-223); residency restarts have none. Each evict attempt bumps the generation (design:189). require_complete=false readers take no budget (store.rs:1879-1880). The timeout covers only singleflight acquisition (store.rs:1893-1898). Cancellation (design:868) is not stated for this path. Termination is unstated. Fix: name a residency restart cap and its error (retryable; reuse ArchiveHydrationRefused), or state the termination argument under bounded reclaim.

7. should Decision 5 "Why this holds" (design:199-206) and pin_during_drop (design:899-901): the mechanism is wrong. A reader that pins after the evictor's pin read (design:190) takes its generation snapshot (step 3.1, design:177, after the step-1 pin at design:172) after the bump (design:189). Its snapshot therefore equals the post-bump value, and the splice re-check never fires. Drop safety rests on residency-gate ordering plus the cleared flag. The generation check restarts only loads that snapshotted before the bump, which is the abandon case. design:203-204 and :900 are false as written and were added in v14. Fix: state gate ordering as the drop mechanism and the generation check as the abandon-restart mechanism. Rewrite pin_during_drop to assert gate ordering, not the generation.

8. should Decision 2 byte bound (design:80, 102, 110-114; I3 heading design:377; bullet design:399-400): "bounded exemption" is kept with no numeric ceiling and no per-entity cap. "Peak is twice the entity's token bytes" is relative to an unbounded input. The query has limit None (embedded/core.rs:306-317), and merged_text concatenates all token text (embedded/core.rs:334-352). "The S1 report measures the largest such entity" (design:113) has no backing item: ledger_owns_heap checks steady-state within 10% (design:812-823), not peak. The 2x figure also counts only charged bytes. Uncharged transients (the owned Vec<Event> from store.query, store.rs:2360; the tokens Vec; the merged_text and json! copies) are excluded, so "peak" is false as a heap-peak claim. r13#5 asked for a ceiling, a cap, or dropping "bounded"; v14 did none of these. Fix: state a numeric ceiling (per-entity token-count or byte cap, enforced before compact_tokens, value measured at S0) with an S1 gate. Or drop "bounded" at design:80, :102 and the I3 heading, and qualify "peak" as the charged-ledger peak.

9. should Decision 4 victim eligibility (design:125-126, 161, 195-198; ineligibility text design:476-477): reclaim takes unpinned tenants from the ledger map. After zero-path eviction a tenant keeps tail bytes (design:195-198, positive resident_bytes()) and a cleared flag. It is selected but frees no durable bytes, and victims and generation bumps (design:189) are spent on zero-gain evictions. design:476-477 excludes tail-only tenants only in the flush_failing failure-mode section, and it says "durable resident data". Derived events are also dropped (design:139-144, :195), so a derived-only tenant is eligible in fact but reads as ineligible at :476. Fix: add one eligibility sentence at design:125-126 or :161 (durable or derived bytes greater than zero; tail-only tenants skipped). Align design:476 to "durable or derived".

11. should Compaction gate claim (design:115-116; caller bullet design:110-116; embedded-only note): "Compaction holds cache_residency_gate.read() from phase 1 through phase 3, so an eviction cannot interleave" is true only inside compact_entity_tokens (store.rs:1405-1431). The merged text is built in the caller (embedded/core.rs:306-317, query with tenant_id None and limit None; merged_text at :350-353). That caller pins nothing (store.rs:2468 ensures load only when tenant_id is Some) and runs before the gate. An eviction between that query and phase 1 leaves pre-eviction token text in the derived event, and phase 3 removes only resident tail tokens. The gate is also not used in compact_entity_tokens in current code, so the claim is unimplemented, and the design does not say so. Fix: take the residency gate or a pin around the caller's query and merge, or move the token read into compact_entity_tokens under the gate. Name that path in the Decision 2 bullet and the embedded-only note.
