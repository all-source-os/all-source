# Organic growth page design: event replay debugging

## Search intent and page job

Target engineers investigating incorrect derived state, projection drift, or production sequences.
Existing platform page owns general event-sourcing architecture; Replay Studio owns authenticated
operation; use-cases page owns broad discovery. New public page owns event-replay debugging intent
and connects chronological evidence, point-in-time inspection, impact analysis, atomic projection
replacement, SDK workflow, and product entry points.

## Content and evidence

Publish `/event-replay-debugging` as source-backed technical service page. Distinguish event-history
inspection, historical reconstruction, projection replay, and deterministic execution replay. Show
current TypeScript SDK analysis-first API exactly as implemented. Link Replay Studio, SDK, API docs,
platform architecture, pricing, and self-hosted repository. Add Article and breadcrumb JSON-LD,
link from `/use-cases`, and add sitemap coverage. Cite primary architecture references and product
source instead of competitor claims.

## Measurement and guardrails

Measure Search Console impressions and clicks for event replay, projection rebuild, and production
debugging queries; clicks into docs, signup, pricing, and Replay Studio; replay impact analyses; and
restart/provenance proof completion. Do not claim replay makes nondeterministic external calls
reproducible, repairs source events, or guarantees root cause. Never place production payloads,
credentials, prompts, or personal data in analytics.
