1. blocking Decision 4 / Acceptance compaction_evict_equals_restart (design:97-107, 677-678): compaction drops non-durable token events from the resident set, and evict plus rehydrate reverts to Parquet only, so unflushed tokens are lost until the flusher runs. Evidence: store.rs:1440-1444 `events.retain` removes every matching token event with no durability check. Phase 3 does not touch `storage.pending`. tests/compaction_history_tests.rs:65-119 shows WAL replay restores these tokens on restart. Decision 4 says the revert is "exactly as a restart does today", which is false for this case. Fix: keep non-durable tokens resident as tail when compaction removes them, or merge only durable tokens, or make the rehydrate merge read `storage.pending`. State the rule in Decision 4 and I4. Extend compaction_evict_equals_restart to durable events plus unflushed tokens at compaction time.
