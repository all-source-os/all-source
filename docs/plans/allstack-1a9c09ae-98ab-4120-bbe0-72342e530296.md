# Implementation plan: Prime typed writes and provenance

## Outcome and user flow

An agent or user defines node and edge kinds through MCP or HTTP, sets enforcement for the authenticated tenant, then writes facts with optional assertion details. Strict mode rejects invalid facts with the field, expected constraint, and received value. Warn mode accepts them and records violations. Open mode preserves existing required-field validation while leaving new typed constraints unenforced.

A caller can inspect any projected node field and see the contributing event IDs and assertions, including actor, model, run, derivation, and confidence. `highest_priority` selects a user correction over a newer extraction. Document extraction records its run and associates every resulting node and edge with it.

Elixir MCP semantic and hybrid search reach Core’s event-search services. Hosted reads use only the tenant established by authentication and refuse requests without that scope. Both Prime HTTP surfaces expose generated OpenAPI documents covering their routed Prime paths.

- Implement a shared validator for `string`, `number`, `integer`, `boolean`, `datetime`, `node_ref`, and `enum`, including required, bounds, length, assertion requirements, endpoint types, and cardinality. Validate updates against merged node state. Return a structured violation containing field, expected constraint, and received JSON value, formatted identically by embedded and hosted paths.
- Preserve existing `{"required":[...]}` behavior in all modes. Open skips new typed constraints; warn records violations and accepts; strict rejects violations and unknown kinds. A persisted tenant-scoped `prime.enforcement.set` event selects mode, with open as the default and the latest event winning on replay. Compatible additions must remain accepted; restrictions that reject previously valid writes must be refused. Record the validated kind version on new node events. Replay projects historical events without revalidating them.
- Keep schema registration and enforcement changes scoped to authenticated tenant. A caller-provided tenant cannot authorize another tenant.
