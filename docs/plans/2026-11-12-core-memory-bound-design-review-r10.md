1. blocking Decision 5 (design:117-125); I8 (design:314-317); pins_whole_reads: pin protocol admits a partial read. Evictor order is bump generation, read pins, evict, clear loaded flag. Reader order is snapshot generation, check loaded, pin, re-read generation. Interleaving: E bumps gen; E reads pins=0; R snapshots new gen; R sees loaded=true (not yet cleared); R pins; R re-reads gen (equal, accepts); E retains durable events; R serves tail-only. Evidence: apps/core/src/store.rs:2145-2152 bump, :2158 events.retain, :2167 and :2197 mark_unloaded after retain; warm fast path checks only loaded (store.rs:1875-1877). Fix: state that the evictor clears the loaded flag (or sets an evicting marker) before bumping the generation, so any reader snapshotting after the bump sees not-loaded. Name this ordering in Decision 5 and in pins_whole_reads, and add the interleaving as a named case. Caveat: if the pin-read then refuses eviction, the tenant must be re-marked loaded.

2. blocking Decision 2 (design:59-68); Decision 9 (design:162-164); reserve_before_lock (design:665-667): follower ingest charges at push, under the store locks. Decision 2 requires reserve before any store lock or entry guard. The reserve_before_lock acceptance exempts only singleflight and permanent-owner charges, so the debug guard would panic on every replicated ingest. Evidence: apps/core/src/store.rs:1053 cache_residency_gate.read, :1054 events.write, :1085 observe_entity_version, :1090 storage append, :1095 events.push, all inside the lock scope. Fix: take the follower reservation before store.rs:1053 (it cannot refuse, so no reclaim runs under the lock), or name follower charges as an explicit exemption with reason in reserve_before_lock.

3. blocking Decision 1 (design:41-52); Decision 8 (design:159-161); owner table (design:385-386, 390-391); I3 (design:267-275): the permanent-owner set is inconsistent. Decision 1 and Decision 8 define permanent owners as entity_versions and version_index_* only. The owner table calls schema_evolution history permanent, though it is charged from the refusable step-1 split. cache_generations is marked permanent but is not in Decision 8 and is inserted under cache_residency_gate.write with no exemption. projection.entity_snapshots is charged on growth and never released, with its charge mode unstated. I3 names no refusal reason covering an owner that can never release. Evidence: apps/core/src/store.rs:2127-2148 (gate.write, then entry().or_insert(0), no removal site). Fix: define one permanent set listing every never-released owner, state infallible-and-exempt or refusable with an I3 reason for each, and carry those reasons into Decision 1, I3, the constraint list and the reserve_before_lock exemption.

4. blocking Owner table, events.resident (design:383); Decision 4 (design:103-113); ledger_owns_heap (design:656-664): release rules are incomplete. events.resident is released only at eviction and only for durable events. Decision 4 eviction also drops derived events, and token compaction removes durable token events from memory with no release or charge row. ledger_owns_heap requires the ledger within 10% of heap after token compaction and after eviction, which the decided rules cannot meet. Evidence: store.rs:1440-1444 (compaction retain); design:383; design:103-108. Fix: add owner-table release rows for compaction (removed token events) and for derived drop at eviction; state the charge lifecycle for the merged derived event; name the reconcile point.

5. blocking Decision 7 (design:151-158); I3 (design:267-275); constraint list (design:340-341): scope of the flush_failing refusal is undecided. Decision 7 says charges refuse with reason flush_failing, which reads as all charges. Query and hydration share the same total-budget path (Decision 3, design:86; Decision 2, design:65-66). The constraint list records only ingest 503. The brief requires byte-identical query results (brief.md:74), so a query 503 under flush failure breaks it unrecorded. Test flush_failure_refuses (design:692-695) names no query or hydration case. Fix: decide query and hydration behaviour under flush_failing, add it to the constraint list and brief, and extend the test.

6. blocking Decision 12 (design:181-183) vs S1 owners table (design:394): the decisions contradict on what geo charges. Decision 12 charges candidate count × per-row cost before building the candidate map. The owners table charges query.geo as rows after the 10,000 clamp, at request end. Acceptance geo_within_query_share (design:704-705) cannot be decided without a candidate-count bound, since the clamp caps results, not candidates. Fix: change design:394 to candidate count × per-row cost, charged before the map, with 503 on overflow; add that refusal to the constraint list and brief, or bound candidate count and show count × p99 cost <= q×B at 5 GiB.

7. should Decision 6 archive budget (design:135-145); fly.toml:44; hydration_restarts_fresh_budget: single-attempt byte headroom for Longhand is undecided. Estimate 201,785 × 3,892 B = 785 MB per attempt, against ALLSOURCE_STRICT_ARCHIVE_MAX_DECODED_BYTES = 805,306,368 (fly.toml:44), about 2.5% headroom. The design does not name the unit of max_uncompressed_bytes (decoded or compressed; storage.rs:39-41, archive_budget.rs:33-35), and does not say whether the 3,892 B figure (design:225) is that unit. Fresh budget per attempt is decided (design:136-138). Not decided: a margin, an S0 gate comparing decoded bytes to the limit (design:368-373 lists payload mean and p90 only), or a fallback if one attempt exceeds the limit (raise fly.toml:44 or fail). Fix: state the unit, measure Longhand's decoded bytes in S0, state the margin hydration_restarts_fresh_budget requires, and decide the over-limit fallback.

8. should Harness > Acceptance A6 (design:644-650) vs Builds (design:515) and Determinism (design:543): A6 budgets "a candidate-worktree build plus two replays" and "the test build plus the full test list". The production-hasher leg needs a second heap_replay build without deterministic-hash (design:515 bracketed feature; design:543), which A6 does not name. Gate prod_hasher_digest_equal (design:601) is hard. Fallbacks at design:649-650 do not measure this build. Fix: add the production-hasher build to A6 as a named phase, or state it is a separate evaluator with its own budget. Record feature and no-feature build timings and fixture regeneration in ceilings-S1.json.

9. should I5 / oracle tie-break orderings (design:294-301; constraint list design:319-349) vs brief byte-identical constraint (brief.md:74, :84-103): the design admits an API-response change for failing archive files ("error precedence may change") that is in neither the constraint-change list nor the brief. Evidence: store_feed.rs:595 by_file is a HashMap, :625 iterates unsorted, :633-635 error precedence. With one archive file the outcome is order-independent, so the change needs two or more files with one failing, where the choice already varies per process. Fix: add a constraint-change item with consequence and error text to the design list and brief, and exclude this path from I5 explicitly. Named test tie_break_orderings (design:773) covers ordering only, not error precedence.

10. should Harness: replay budget B and Production budget: B = 1.1 × T_fixture / (1−q) (design:554) uses an undefined T_fixture. The production derivation (design:448) uses T = 3.25 GB for the largest tenant. The 25% fallback (design:649-650) does not say it keeps the largest tenant at full shape, so replay_budget_holds_largest_tenant (design:771-772) may stop exercising it. shape.toml (design:522-523) does not pin the largest tenant. Fix: define T_fixture as the largest fixture tenant's events plus indexes, measured by the ceilings step, and state that the fallback keeps the largest tenant at full shape.

11. should Decision 3/4 reclaim scope (design:85-90) vs system metadata (design:392; system_store.rs:424-443; CLAUDE.md): the design never decides residency for the system store. System events sit in their own WAL and resident set, outside the ledger's eviction map, so reclaim cannot evict them as written. The gap is that the design never says so, never states refusal behaviour for a system charge, and has no acceptance test. Non-folded domains are never released (system_store.rs:90-92). Auth and tenant writes reserve through it (event_sourced_auth_repository.rs:118,136; event_sourced_tenant_repository.rs:273). Fix: decide system_store residency explicitly (outside the victim set, charged, released only by checkpoint fold, counted as permanent or bounded), add an I3 refusal reason or exemption, and add an acceptance test for system-stream writes under budget pressure.

12. should Delivery (design:869-880; design:875; design:879) vs run base commit and S1 deploy head: collapse is not ordered against the autoresearch run. SKILL.md:77-82 requires HEAD to stay at the frozen base commit through verify, report and export. Collapse rewrites the SHAs the design cites: "the oracle commit" (design:303, :524, :833), the S1 structural commit (design:603), and the S1 baseline. The design says "one commit per author before the PR leaves draft" (design:879) without saying when, and does not say whether gates re-run on the collapsed SHA. Fix: state that collapse follows the last run command and the S1 deploy, re-run gates on the collapsed head, and pin report SHAs to a reachable ref (tag or branch) or tree hashes.

13. should Acceptance list (design:652-783) vs Decision 1 boot check (design:55-56) and Decision 13 "Release builds never enable it" (design:190-191): no named acceptance test covers the boot refusal or the release-feature absence. Only heap_profile_nonempty (design:764) exists. "Machine memory" is undefined (physical RAM or cgroup/Fly memory_mb). hydration_admission.rs:66 holds the existing ALLSOURCE_MEMORY_RESERVE_BYTES reader. Fix: define the machine-memory source, then add boot_refuses_budget_over_machine_minus_reserve and release_build_has_no_heap_profile.

14. should Harness gates (design:596-609) vs SKILL.md:121-122 ("A gate that has never rejected anything is untested"): no hard gate has a negative control. Gates query_digest_equal, ledger_two_sided, rows_decoded_ok and others are shown only passing at baseline (design:846). Fix: add a named negative-control test per hard gate (seeded wrong digest, ledger off by 20%, rows_decoded above ceiling, dropped test name), and record that each gate fails on its control before the baseline.

15. should Harness mutable paths (design:637) and tests_pass gate (design:606): the mutable root holds inline and sibling test code. Inline #[cfg(test)] appears in 185 files under apps/core/src, plus 16 *_tests.rs siblings. expected_tests_ran checks names only (tests-S1.txt, design:503), and no gate hashes test bodies. Replay digest gates (design:600-606) cover the replay path, not error paths or edge cases. Fix: pick a mechanism. Per-file protected_paths is too coarse for files mixing prod and test code. A baseline hash of test regions or a test-body digest gate fits better. State which one applies.

16. should Harness protected paths (design:637): "The baseline check fails if any listed path is missing" names no owner. manifest.md:55-61 has no existence rule, doctor only schema-checks (r9#17), and no acceptance test covers it. Fix: name the owner (an evaluator check or harness step) and add a test to the acceptance list, e.g. protected_paths_exist.

17. should Harness fixture regeneration under verify (design:524-526): "verify regenerates it in its fresh directory with the same binary" does not say whether that is the oracle-built heap_fixture or a rebuild at the kept candidate. Those can differ, since heap_fixture links mutable apps/core/src code, and verify requires exact equality of peak_live_mib (SKILL.md:275-280). The shared --target-dir (design:512) can overwrite the oracle output. Fix: pin the oracle-built heap_fixture by SHA-256 as a literal manifest argument, state that candidates cannot change it, and state how verify obtains a matching binary.
