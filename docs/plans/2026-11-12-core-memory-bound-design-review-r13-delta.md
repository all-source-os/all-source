1. blocking Decision 5 warm path, `ensure_tenant_loaded` contract (design:151-166, 897-899): step 2 returns the guard when the loaded flag is set, with no `require_complete` check. Design text also says `is_complete` reads the AtomicBool flag, and "tenant_loader keeps the integrity bit" (design:153-154). The code differs. `tenant_loader.rs:167-169` `is_complete` reads the stored integrity bit. The fast path at `store.rs:1869-1876` is `is_loaded && (!require_complete || is_complete)`. The only in-tree `require_complete=true` caller is `store_feed.rs:490-491`, which errors with "feed archive certification was evicted; retry" when `!is_complete`. Under the v13 text that check is vacuous and partial tenants pass feed certification. Evidence: design:153, :154, :161; `tenant_loader.rs:58-62, 167-169`; `store.rs:1869-1876`; `store_feed.rs:490-491`. Design never mentions `require_complete`. Fix: define `is_complete` as loaded flag AND integrity bit. Make pinned step 2 "loaded AND (!require_complete OR complete)". Name `require_complete` in the entry-point signature (the code's `ensure_tenant_loaded_with_limits`, `store.rs:1871`, while the design says `ensure_tenant_loaded`). Cover it in `pins_whole_reads`.

2. blocking Decision 4/5 pin-zero success path (design:124-129, 139-140, 176-177): eviction keeps the not-yet-durable tail resident, but pin-zero "drop the events and call `tenant_loader::mark_unloaded`, which clears the bytes and last_used". `mark_unloaded` (`tenant_loader.rs:181-185`) removes `loaded`, `bytes` and `last_used`, and also removes the integrity entry, which the design never states. The resident tail's bytes leave the budget total (`total_bytes`, `tenant_loader.rs:204`, used by `over_budget` at :102-104). Rehydration does not restore them: `append_loaded_event` (`store.rs:2261-2263`) skips already-resident ids before `add_bytes` (`store.rs:2292`). Evidence: design:128-129, :139, :176-177; `tenant_loader.rs:181-185, 204`; `store.rs:2261-2263, 2292`. Fix: state which events are dropped (durable and derived, per design:139). Set bytes to the kept tail's sum of `estimated_size_bytes`, not 0. Name the replacement for `mark_unloaded` that keeps bytes and `last_used`. State that the integrity entry is removed.

3. blocking Decision 5 abandon path (design:172-175, 897-909): (a) `mark_loaded_with_integrity(captured)` does not match the signature `(tenant_id: &str, complete: bool)` at `tenant_loader.rs:171`. (b) It stamps `last_used = Instant::now()` (`tenant_loader.rs:172-173`), so the design's "later of captured and current" rule is not what the call does. Same max rule is repeated at design:907. (c) `begin_evict`, `abandon_evict` and `ResidencyPin` do not exist in `apps/core/src` (grep: only `store.rs:1671 ensure_tenant_loaded` exists) and are not marked as new. (d) "Restores the bytes" names no method. `add_bytes` (`tenant_loader.rs:190-192`) is additive only, and no setter exists. (e) Ownership conflict: design:155-165 makes the AtomicBool the single owner of loaded-ness and replaces `DashMap<String,bool>`, but `mark_loaded_with_integrity` writes the DashMap at `tenant_loader.rs:172`. Evidence: as cited. Fix: write `mark_loaded_with_integrity(tenant_id, captured.complete)`, or name a new setter that writes the AtomicBool. Mark `begin_evict`, `abandon_evict`, `ResidencyPin` as new. Name a bytes setter. State `last_used` as an exact operation (max of captured and current via a named setter, or stamp now and say so) and make design:907 match.

4. should Decision 5 pin lifetime, #1 (design:159-164, 170, 176-177, 183; acceptance `pins_whole_reads` design:897-905): the proof claim "no reader holds a guard over a tenant whose events are being dropped" is false. Window: evictor reads pin=0 (design:171). A reader pins (step 1, design:159-160) and reads loaded=false (:161), since the flag is cleared at :169 before the pin read. It takes the cold path under its pin (design:180-181). The evictor then drops events and calls `mark_unloaded` (:176-177). Also, :170 says "hydration's splice checks use" the residency generation, but reader steps no longer snapshot it (v12 had "Snapshot the generation", removed in v13). The design has no check point, and no rule that splice or mark writes take the residency gate. Abandon during an in-flight cold load can overwrite integrity set by that load (`tenant_loader.rs:171-174`). Read safety mostly holds because the read happens after the guard is returned. The decision is not shown wrong; the proof and the rule are. Evidence: design:159-164, :170, :176-177, :183; v12 diff `d69e8ad` steps removed in v13. Fix: state that the cold-path splice and loaded/integrity writes run under the residency gate, or name the generation snapshot point and its re-check before splice. Reword :183 to "a cold reader may pin during a drop; its splice runs after the gate is released and re-checks generation". Add acceptance cases for pin-after-pin-read-before-drop and for abandon during an in-flight cold load.

5. should Decision 2 token compaction exemption (design:103-112, 106-107; I3 design:357-362): the exemption is labelled "bounded" with "the overshoot is one event". That bounds a count, not bytes. The merged event is the concatenation of all token text for one entity (`embedded/core.rs:334-352`, `merged_text`), so its size grows with the token count. Query at `embedded/core.rs:306-317` has `limit: None` and no cap. No byte ceiling or per-entity cap appears anywhere in the design. The phrase "never reclaims" is wrong; whole-tenant eviction reverts the merged event (design:139-146). Evidence: `embedded/core.rs:306-317, 334-363`; design:103-107, :362. Fix: state a byte bound for the merged event (for example sum of durable token `resident_bytes()` per entity, measured at S0 with a stated ceiling), or a per-entity token-count cap enforced before merge. Put the number in I3 and in the S1 report, or drop "bounded".

6. should I3 overshoot sources and Decision 1 Size (design:46-59, 51-52, 357-358, 229-230, 477): I3 says every infallible owner is "bounded as decision 1 (Size) states". Decision 1 gives no bound for Prime projections: design:51-52 says their keying "is not yet checked, and S0 records it". `system_store` is bounded only to the one-year horizon (design:58-59: "Beyond that horizon, growth stays unbounded"). The deploy gate covers only `system_store` (design:55-56). `entity_snapshots` is also missing from the I3 list, as r12#6 asked. Evidence: as cited. Fix: name the owners with no bound yet (Prime projections, `system_store` beyond horizon). Say they are measured by S0. Gate `system_store` by the S1 deploy gate. Give Prime projections a bound in Decision 1, or exclude them from the I3 bounded claim and list them as unbounded known limits. Add `entity_snapshots` to the I3 list.

8. should I5 excluded responses (design:373-377; brief:85-86): the list "Constraint changes 1, 2, 3, 5, 7, 8, 9 and 11 change responses" omits constraint 10. The refusal depends on host available memory, not on replay content. Evidence: as cited. Fix: add 10 to design:374 and brief:85-86, or state that the replay host has headroom so the refusal cannot fire.

9. should I5 rationale for constraint 7 (design:374-377, 682-692): "the rest because the replay set contains no request that reaches them" is false for constraint 7. The replay set includes "one event-feed page" and "a read-model commit built from the feed head" (design:686-687), both on the feed epoch path (`store_feed.rs:135-143`). Exclusion works only through "Feed epochs are normalized" (design:690-691), which I5 does not cite. Residual gap: normalization covers epoch values, not status. A pre-eviction cursor in pass B would return 409 VersionConflict, and the design does not say whether a replay request carries a stale cursor. Fix: give per-constraint reasons. 7 by feed epoch normalization (design:690). 11 by no failing archive file in the replay set. 1, 2, 5, 8, 9 by absence of those requests. Address the stale-cursor case.

11. should Decision 5 "One entry point, one guard" (design:155-157): the claim that `ensure_tenant_loaded` is "the only way any reader reaches resident events" is false. `compact_entity_tokens` reads events in Phase 1 with no pin or gate (`store.rs:1405-1420`, read at :1416) and writes at `store.rs:1431` under the write lock. Other unpinned event readers include `store.rs:1179` (`total_events`), `:1190` (`events_after_offset`) and `:1381` (`snapshot_events`). `store_feed.rs:295` and `:401` take `self.events.write()` but only after `cache_residency_gate.read()` (about `store_feed.rs:287` and `:393`), so they are gate-protected, not pin-protected. Embedded tenants are evictable (design:414), so the compaction race is live. Fix: name compaction explicitly as embedded-only and state that it takes the residency gate or a pin. Correct the store_feed description to "gate-protected writes". Name the other readers, or state they are exempt with reason.

12. nit Security, six hydrated tenants (design:981-984; Context security): two problems in one sentence. "Hydration does not need authentication, so the design does not claim they are a subset of those four" is uncited and overgeneralized. Skip-listed routes need no auth (`infrastructure/security/middleware.rs` AUTH_SKIP_PREFIXES), but `/api/v1/event-feed` and `/api/v1/read-models` authenticate and take the tenant from the credential. Also missing is r12#15's explicit "the other five hydrated tenants are not identified as ours". "Only Longhand is named" does not say that. Fix: write "hydration through skip-listed data-plane routes needs no authentication, and the other five hydrated tenants are not identified as ours", and cite `middleware.rs` AUTH_SKIP_PREFIXES.

13. nit Decision 2 no-op release wording (design:106-111): the compaction charge is called "charged infallibly" (additive counter) and then "an RAII reservation that drops with the event". A reservation and an infallible charge are different. The release on the phase-1 no-op return is implied, not named. Evidence: design:106-111; `store.rs:1418-1421`. Fix: pick one term. Say "infallible charge released by a drop guard that owns the merged event's bytes".

14. nit Decision 2 cite and acceptance wording (design:110; acceptance `pin_released_on_every_path` design:847-848): cite says `store.rs:1419-1421`; the return is at `store.rs:1420-1421`. The test says "pin count is 0" after a successful load, which holds only after the caller drops its guard. Fix: cite 1420-1421. In the test, state that the guard is dropped before the count is read.
