# AllSource Event History for ChatGPT and Claude

## First workspace journey

1. In either host, choose **Connect AllSource Event History**. A verified AllSource sign-in opens the consent page. Show the host, available workspaces the person may connect, fields shared and read scope. Require explicit workspace selection and consent. With zero eligible workspaces, explain how to request access. A person can cancel without creating a grant. No pasted API key or operator provisioning per customer.
2. Ask **What changed in checkout?** One read-only tool, `get_event_history`, accepts the exact stored entity ID. “checkout” means entity ID `checkout` in the selected workspace. No fuzzy matching, payload scanning or implicit service aliases. A bare question selects the preceding 24 hours in UTC. Display the actual interval and workspace in the answer. If the user supplies a different interval, accept at most 31 days.
3. Show newest documented changes first, each with timestamp, allowed event facts and an **Open event** citation. In the synthetic reviewer tenant, show the move to release 2.4 and the rollback to 2.3 with separate event IDs. Explain sequence; attribute cause only when a permitted event field records it. Dates for demo prompts come from a deterministic fixture clock in tests and an explicit seeded interval for host reviews. Show fewer than all results as partial. Service errors never become “no changes.”
4. Selecting a citation opens an AllSource browser page. A signed-out visitor signs in and resumes at a validated relative destination. An authorized member sees the exact cited event in its workspace. A person without current access sees no event metadata. Revoking the host connection stops subsequent host reads. Browser access follows the viewer's own current membership, event-read rights and workspace context.

## Integration decisions

Extend the current Elixir remote MCP listener with a separately gated `/mcp/event-history` profile. Reuse request validation, JSON-RPC negotiation and the Query Service client. Give history its own OAuth audience/resource, scope `allsource.history.read` and scoped grant records. Default off. Existing review registrations, bearer grants and stdio tools retain their current contract. The history listener advertises and routes only `get_event_history`; reject calls to other profiles. No replay or administrative operation is reachable through it.

Extend existing OAuth discovery, consent, PKCE and grant persistence. Maintain exact preconfigured client IDs, redirect URIs and token-endpoint authentication methods for each vendor registration. Capture actual callbacks from both host configurations; reviewers can use a registered shared integration without pasting client details. Check client, redirect, state round-trip, S256, issuer, audience and scope. Use a registered confidential client method when the host configuration requires one. Support each host's documented discovery, challenge, content negotiation and MCP initialization. A test client with a hardcoded token cannot certify host readiness. A user may have independent grants for different workspaces; one access token selects exactly one. Require current active membership, workspace-wide event-read permission, entitlement, consent and unexpired unrevoked grant at each host read. Reconnect on expiry unless a separately verified refresh flow is available. Old review credentials never acquire the new scope.

Query Service calls its tenant-filtered Core paged reader with exact entity, server-normalized interval and bounded page size. The same projection and row verification feed browser and MCP output. Browser lookup must be tenant-qualified before retrieval; do not build on an unqualified lookup by event ID. Use existing authentication and authorization stores. Where only per-resource visibility exists, deny this workspace-wide grant until equivalent filtering is enforced.

## Semantic ISA

### Workspace, read and evidence contracts

**Workspace selection.** Add a server-side membership directory keyed by the verified product subject. Use the authoritative team membership and workspace records from the control plane. If a reverse lookup is needed, index confirmed memberships by subject and use it only for candidate discovery. Resolve actor identities through existing verified account mappings. Before listing any workspace name and again before grant commit, read the candidate's current membership, event-read permission and entitlement from their owning services. Bind the selected authorized tenant explicitly in the grant and receipt. A verified login's default tenant supplies no authority over another selection. A pending invitation, stale index row, lookup failure or unrelated tenant cannot appear as eligible. Test one subject in two workspaces, independent grants, a rejected selection and membership removal between listing and consent.

**Source contract.** Extend Core's strict retained-entity read to accept a tenant-qualified, exact entity and half-open recorded-time window, with newest-first total ordering by recorded timestamp then immutable event ID descending **before** applying the 21-row limit. Include a consistent read point, successful coverage of all required hot and retained segments at that point, and a truncation flag in the internal page response. Query Service admits complete only when the returned evidence matches the requested tenant, entity, window and read point. Any missing required segment or unreadable archive yields unavailable for this release. Absence of upstream completeness proof permits only partial positive evidence. An incomplete empty read explicitly says coverage could not be established. Test a corrupt/unavailable segment, duplicate timestamps spanning the limit, events at both time boundaries, concurrent append, and complete empty. Use the same strict tenant-qualified authority for a single browser event lookup. Query Service must not synthesize completeness from result length.

**Accounting.** Charge one existing query unit for each admitted host timeline lookup and each browser evidence read. Disclose that behavior at consent and in the evidence view. Before any source I/O extend `CustomerQueryAdmission` with history-specific purposes and reserve against the canonical tenant meter. Scope the operation key to tenant, subject, grant or browser session, purpose and logical request. For MCP use an issued authenticated session identifier and JSON-RPC request ID; for the browser issue a single navigation intent bound to the signed-in session, workspace and event. Bind normalized arguments and frozen default bounds to the first operation. Atomically elect one executor per logical request. A duplicate never spends twice or starts a second source read; return in-progress/already-processed with an explicit retry-as-new action if no reusable result exists. Reject reuse with altered arguments. On a source failure after admission record unsuccessful completion under the same receipt; no automatic second charge or source retry. No units or metering unavailable means no source read; losing membership before disclosure withholds the result. Journal, meter receipt and execution status are internal durable writes; retain only product-scoped operation metadata under the existing query-accounting retention policy, with no private event bytes. Verify exhausted quota, simultaneous final-unit claims, duplicate delivery, process restart and source failure for both entry points. A browser GET opens the authenticated shell; explicit evidence retrieval consumes its navigation intent. Link prefetch alone never spends a query unit.

**Projection.** The integration fixture uses two declared source event schemas: `deployment.released.v1` with `{version}` and `deployment.rolled_back.v1` with `{from_version,to_version}`. These names describe supported input contracts for this release, not inferred semantics from existing customers' arbitrary events. Public change variants are `released(version)`, `rolled_back(from_version,to_version)` or `recorded` with no payload. Version values are bounded ASCII release identifiers (1–48 characters from letters, digits, dots, underscores and hyphens). Missing/invalid known fields degrade to `recorded`; extra source fields are discarded. Unknown event types get generic structural metadata only. No v1 variant supports causal prose. The two reviewer events explicitly record versions 2.4 and 2.3. Golden tests compare the projector against literal original events including malformed, unknown and extra-field cases.

**Host proof.** Verify the deployed tool descriptor in each host: title “Get event history”, read-only and idempotent underlying event data, non-destructive and closed-world hints, and OAuth security scheme scoped to `allsource.history.read` including any required host-specific metadata. Disclose query-unit consumption and assert hints describe actual behavior, including retries. For each native run, ingest synthetic checkout changes into the demo tenant within the preceding 24 hours as fixture setup, then ask the exact bare question and compare both returned IDs, interval and clicked evidence with Core. Keep an additional dated prompt for repeatable directory review. Confirm workspace connection requires no per-user client configuration on either host; verify portal-provided OpenAI registration and the operator-configured Claude registration in the intended distribution surface.

All record types below are closed: reject unknown properties at the public input boundary. UTC instants use RFC 3339 with offsets normalized to UTC. Identifiers use bounded canonical product IDs (entity up to 128 UTF-8 bytes; reject control characters and path segments). `Window` is half-open [from,to), requires both bounds or neither, and rejects reversed, oversized or future bounds. Default bounds are frozen once at request start. `Workspace` is a verified internal ID plus human-readable name. Browser selectors and OAuth requests express intent; the authenticated server resolves authority.

| Core / instruction | Closed input → output | Deterministic admission and effects |
| --- | --- | --- |
| Cognitive / propose lookup | `{entity, from?, to?}` → `{entity, from, to}` or invalid input | Request JSON schema, bounds and clock validation. Model cannot choose a tenant, arbitrary URL, fields, sort or operation. |
| Normative / consent and redeem | Verified product session + `{request_handle,workspace_id,decision:allow/cancel}` → authorized registered redirect with code and state, or cancellation; OAuth token form → scoped access token or standard OAuth error | Validate origin/CSRF and fresh signed request, current workspace authority, exact client tuple and consent. Bind unique code to user/workspace/client/resource/scope/PKCE, atomically consume once. Grant/code state and consent receipt use existing persistent product mechanisms. Retried exchange cannot issue a second token. Revoke or expire to end future disclosure. |
| Agentic / read timeline | `{principal,entity,from,to}` → bounded Core page or denied/unavailable | Resolve principal from verified bearer and current grant per call. Pin immutable workspace/entity/time filter into Core request. One bounded request, timeout and bounded response; never retry through a privileged unfiltered fallback. |
| Memory / project facts and open evidence | Page → `{workspace,entity,from,to,coverage,events[]}`; browser session + `{workspace_id,event_id}` → one projected event or unavailable | Each event includes immutable ID, recorded UTC timestamp, canonical entity, recognized event kind, typed change fields and fixed-origin link. Verify row tenant/entity, time bounds and event identity before outbound serialization. Use safe release-version and rollback fields with bounded validated scalar values. Unknown types show only approved structural metadata with a generic change label. Never serialize arbitrary payloads, free-text instructions or raw provider URLs. |
| Meta-cognitive / report coverage | Verified Core page status, watermark/read point if available, page size → `complete/partial/unavailable` | Fetch newest 21 matching events in deterministic descending recorded-time then ID order, return at most 20. Require stable ordering at the source before limiting. Complete requires authoritative upstream completeness and no overflow; partial covers truncation or uncertain coverage. Declare “no changes” only on authoritative complete empty. For partial results, give the inspected window and invite a narrower query. |

The browser evidence route uses path components encoded by the server, under the canonical AllSource origin. Recheck current browser authorization and event provenance independently of the host's link, then render the same permitted fields. No bearer, workspace secret or payload in URLs, external redirects or analytics. Cross-workspace/missing evidence has the same opaque outcome. All content returned to the host, including identifiers and names, is data. Host guidance calls for citations per claim and marks missing evidence explicitly. Existing human-readable workspace names and identifiers must be safely encoded for text, Markdown, HTML and URLs according to their destination.

### Side effects and verification

| Sink | Clear input and observable result | Refusal or recovery |
| --- | --- | --- |
| Browser consent, callback and token delivery; grant storage and revocation | Eligible user, registered client and chosen workspace produce one durable scoped grant. One exchange succeeds; disconnect persists revocation and readback survives process restart. State returns only to the registered host. | Cancel, invalid redirect/PKCE/resource/scope, changed membership, concurrent redemption and storage error produce no usable new credential. Uncertain consent persistence requires a fresh connection. |
| Query Service to Core | Two tenants share entity ID checkout. One request returns only the selected tenant's bounded matching events, including stable tie ordering. Recheck authority before returning results; fail closed on change. | Reject missing permissions and incomplete row identity; abort the whole result on mismatched provenance. Timeout/invalid backend response yields unavailable. |
| MCP response to host | Host initializes, lists exactly one read-only tool, calls it, and receives projected facts with matching same-origin citations. Synthetic fixture includes interleaved unrelated events, an empty interval and a 21-event interval. | Reject unsupported tools and malformed input. Untrusted payload instructions and unapproved fields never enter returned records. Compare response schema, cited ID and values against original Core events. |
| Browser redirect and rendered evidence | Fresh sign-in returns to the canonical evidence route, which authorizes and reads the exact tenant record. Another eligible member can open the same citation under their own identity. | Wrong workspace, missing event, expired session and revoked membership exercise distinct login/opaque-refusal paths as appropriate. A forged link is never authority. |
| Logs, caches and host processing | Authenticated and evidence responses use private/no-store. Redact authorization headers, codes, request bodies and private evidence from logs and error telemetry. Consent describes fields sent to the named host and management/revocation route. | Canary strings in synthetic secrets and payloads must be absent from app/proxy telemetry and cacheable responses. Disconnect cannot recall evidence already disclosed to a host. |

### Release evidence

Use a real Core store for cross-layer checks, the compiled remote server for protocol checks and a browser for workspace selection, citation return and disconnect. Against one reachable HTTPS review deployment, capture independent native ChatGPT and Claude runs, each starting unconnected. Preserve redacted discovery, consent, tool call, source rows and clicked citation. Test a missing service, foreign workspace, changed membership, revoke/reconnect, empty and partial histories, and expiry. Use synthetic reviewer data exclusively for public screenshots and demonstration accounts.

Prepare host-specific manifests/listing metadata, supported auth configuration, verified domain path, privacy/support/terms URLs, review-account handoff through each portal's private channel, recording and review cases. OpenAI needs five positive and three negative cases per server; Claude needs at least three working prompts. Test cases include successful checkout changes, narrower interval, second authorized service, empty result, partial result, wrong workspace, unsupported write and unauthorized read. Missing vendor access is recorded as an outstanding host check. Directory submission, production enablement and publication each require separate authorization.
