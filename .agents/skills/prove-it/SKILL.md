# prove-it — AllSource Chronos

Generated by `forge-prove-it` from a census of `all-source-os/all-source` at `main@b6614086`.
Every fact in `references/` carries the command that observed it. Re-run
`/forge-prove-it --update` when a workflow, a filter key or a gate moves; a stale ledger
delegates to a check that no longer looks.

> The unit of review is a **claim** ("this ships X"), not a line. The question is always *"is
> there a path where X does not happen?"*, never *"is this code wrong?"*.

Two properties keep this above a generic opinion:

1. **It only reviews what no check covers.** The un-gated set is computed from the ledger.
2. **A finding must be reproduced, and a kill must be evidenced.** Neither side asserts.

## Standing facts — print on every review

- **Nothing here can block a merge.** `gh api repos/all-source-os/all-source/branches/main/protection`
  returned `404 Branch not protected`; `gh api …/rulesets` returned `[]`. A red run is visible and
  a human can merge past it. *"CI would have caught it" is never an answer here.*
- **The default workflow pushes straight to `main`** (repo `CLAUDE.md` § Git Workflow). On that
  path CI runs **after** the code has landed, so a review of a commit range is the only check
  before it ships.
- **No hook is committed to this repo.** `git ls-files '.husky/*' '.githooks/*' 'lefthook*'
  '.pre-commit-config.yaml'` returns nothing. On the census machine a global
  `core.hooksPath=~/.git-hooks` (from `~/.gitconfig`) disables `.git/hooks` entirely. There is no
  pre-push gate behind CI.
- **Orphans — declared, run by no workflow:** see `references/coverage-ledger.md` § Nowhere.

## Arguments

```
/prove-it [<PR number> | <base>..<head>] [--deep] [--post]
```

No argument: the open PR for the current branch; on `main` with no PR, `origin/main@{1}..HEAD`
when the reflog has it, otherwise ask for the range. Never guess a base.

## Phases

| Phase | Mechanical / judged | Agents |
|---|---|---|
| 0 — Frame: range, liveness, claims, hunk coverage | mechanical + one echo | 0 |
| 1 — Ledger + owned probes | fully mechanical | 0 |
| 1.5 — Size the run, a decision router advising | mechanical + one router call | 0 |
| 2 — Lenses, gated by diff surface | judged | 0 inline; 1 per triggered lens when sized `fan-out` |
| 3 — Counter-refutation | judged, evidence-bound | 0 inline; 0–2 when sized `fan-out` |
| 4 — Manual routing | mechanical table join | 0 |
| 5 — Emit | mechanical | 0 |
| 5.5 — Self-audit of the assembled emission | fully mechanical | 0 |

### Phase 0 — Frame

1. Resolve the range. For a PR: `gh pr view <n> --json baseRefOid,headRefOid,state`. A `MERGED`
   branch is dead; review the merged commit on `main` instead.
2. `git diff --stat <base>..<head>` and `git diff -M --name-status <base>..<head>`.
3. Extract claims from the PR body or commit messages. Shapes:

| Shape | Lenses | The thing to refute |
|---|---|---|
| `ships-behaviour` | all triggered | the behaviour never happens on some path |
| `fixes-defect` | guard, wiring, second-item | the invariant is unasserted, or a sibling call site still has the bug |
| `adds-guard` | guard, cosmetic | the guard is unwired, or its pattern matches nothing |
| `refactor-no-behaviour-change` | reuse, guard | the **absence** of behaviour change |
| `NOT A CLAIM` | none | "improves reliability" asserts nothing; say so rather than hunting it |

4. **Hunk coverage:** every changed hunk maps to at least one claim, or is listed `unclaimed`.

### Phase 1 — Ledger and owned probes

Join the changed paths against `references/coverage-ledger.md`. Each changed path lands in exactly
one bucket per check. Only **FIRES, covers it** silences the panel for that check's remit.

Run every probe in `references/cosmetic-probes.md` and `references/guard-ratchets.md` **at HEAD
and at base, and report only the delta.** Nothing in this skill stores a count.

### Phase 1.5 — Size the run

| Size | What runs | When |
|---|---|---|
| `inline` (default) | The main thread attacks the 3–5 highest-risk hops the selected lenses name (removed-symbol callers, the runtime source of a config value, a gate's enforcement point, a new state's lifecycle triggers) with grep and file reads, and kills its own suspicions with evidence. No agents. | every run, unless the row below applies |
| `fan-out` | one refuter agent per selected lens, then counter-refuters | `--deep`, or the router allows a subagent **and** the inline pass left a claim unsettled |

Router: when the `jev-decision-layer` skill is installed, call the `route` command it names
(resolve it from that skill on this machine, never from a path written here) with a `goal` that
names no repository, customer, path or diff line:

| Router action | Do |
|---|---|
| `reuse_cache` | a review already exists at this head; print it and stop |
| `allow_subagent` | `fan-out` allowed, for the unsettled claims' lenses only |
| `stop_retry` | do not re-run the failed lens set; route its claims to the hand-checks |
| `ask_human` | ask before posting |
| anything else | stay `inline` |

The router is advisory. A size that differs from its action is stated in one header line; an
error or timeout means `inline` with `router: unavailable`; no skill installed means `router: none`.
Header: `size: inline|fan-out · router: <action|none|unavailable>`.

Fan-out capability is tested, not assumed: if the host cannot spawn an agent, run the lenses
sequentially in one context, each writing its findings to a scratch file before the next starts,
and print `sequential (no fan-out available)` in the header.

### Phase 2 — Lenses

Select every lens whose surface the diff touches. **Err toward including a lens.** Print each
skipped lens with its reason.

| Lens | Attacks | Selected when the diff touches | Reference |
|---|---|---|---|
| **L1 placement** | wrong app / crate / SDK / service; Core doing Query Service work | more than one top-level unit, a new file, a new dependency, a Dockerfile | `references/placement-map.md` |
| **L2 reuse** | a new abstraction that reinvents a shipped seam | a new file or a new exported symbol | `references/patterns-index.md` |
| **L3 guard-weakening** | a gate loosened, a flag dropped, a filter narrowed, a suppression added | `.github/workflows/**`, any manifest, `deny.toml`, `.golangci.yml`, `.credo.exs`, `.dialyzer_ignore.exs`, `biome.json`, `rust-toolchain.toml`, a suppression comment | `references/guard-ratchets.md` |
| **L4 cosmetic** | dead code, a test that cannot fail, an unwired gate, doc-only completion | **always** | `references/cosmetic-probes.md` |
| **L5 wiring** | the missing hop, in **both** directions, across Core → gateways → SDKs | a route, a handler, a wire type, an SDK method, a contract fixture, an env var | `references/wiring-and-second-item.md` |
| **L6 second item** | the 2nd element, the failing element, the exit paths, the re-run | **always**, plus any state decision: a returned status, an enum arm, an early return, an error arm | `references/wiring-and-second-item.md` |

### Phase 3 — Counter-refutation

`inline`: the main thread tries to kill each finding itself, at the same evidence bar. `fan-out`:
zero findings spawns zero counter-refuters; one or two spawns one; three or more spawns two. Each
counter-refuter gets the documented kill for the exact probe that produced the finding. Join
verdicts to findings in code; hand the report step only the joined result.

### Phase 4 — Manual routing

Join un-settled claims and bucket-3/4 paths against `references/manual-verification-routes.md`.

### Phase 5 — Emit

Blocks, in this order. Order is load-bearing.

| # | Block | Prints when |
|---|---|---|
| 0 | header | always |
| 1 | `CLAIMS` + `UNCLAIMED HUNKS` | always |
| 2 | `VERIFY BY HAND` | **always** — "0 items, no hand-check owed" is a real outcome |
| 3 | `FINDINGS` | when any survived |
| 4 | `ATTACKS TRIED` | always |
| 5 | `LEDGER` | always, with the standing facts above |
| 6 | `CONSIDERED AND DROPPED` | always |
| 7 | `NEXT` | when there is a finding worth tracking |
| 8 | `SELF-AUDIT` | always |

Header: `prove-it · <branch> · <base>..<head> · <n> lenses, inline|parallel|sequential · size: … · router: …`

Per claim: `HOLDS` · `REFUTED` · `UNVERIFIABLE HERE` · `NOT A CLAIM`.

**Verdict** — the first line, exactly one of:

```
🔴 DON'T MERGE — <n> thing(s) broken, fix on this PR
  1. <what breaks, for whom, in plain words>
🟡 MERGE AFTER CHECK — <n> thing(s) nobody tested
  1. <what to check, in plain words>
🟢 MERGE — does what it says
```

- 🔴 when any defect finding stands (`BLOCKS-CLAIM` or `SILENT-RISK`).
- 🟡 when none does, but an **outstanding** hand-check or a `WRONG-PLANE` finding remains.
- 🟢 otherwise.

On a direct-to-`main` range the verdict reads `🔴 BROKEN ON MAIN — fix forward` /
`🟡 CHECK ON MAIN` / `🟢 HOLDS`, since there is nothing left to merge.

Each numbered verdict line names the consequence, never the method: no lens names, tags, tiers or
paths. Those belong in `FINDINGS`. Write terse: fragments fine, technical terms exact, one idea per
line, an empty section is one line ("none").

Hand-checks carry two counts; only **outstanding** (a claim the panel could not settle) gates 🟡.
**Routine** (owed because no check watches the path) never gates the verdict.

Every finding carries a consequence: `BLOCKS-CLAIM` (a claim's own path fails now) ·
`SILENT-RISK` (works now, the next regression is invisible) · `WRONG-PLANE` (works, will need
re-landing in another app). And a tier: `rock` (reproduced; a defect) · `sand` (a hand-check with
a pass criterion) · `water` (unmapped; say what would map it). Never a number, never a duration.

Hand-check item — every field resolves, or the item is refused:

```
N. <claim-id | check-id> · <what to verify>
   why    <why the repo cannot answer this>
   run    <command, verified to exist this session>
   then   <steps, or "no runbook exists — describe the run you did">
   read   <store or log, with the exact query, and WHICH Core: local Docker, Fly, or embedded>
   pass   <an observable criterion, never "looks right">
   caveat <where the runbook itself is unreliable>
   ask    <the substitute question, when `then` has no runbook>
```

Cap the list at 6, ranked by claim-criticality; print `+N routed, not shown` when it truncates.

### Phase 5.5 — Self-audit

Read the assembled report before printing it:

- every cited `file:line` re-read at HEAD this session; a citation that does not say what the
  finding claims drops the finding, and the drop is printed;
- every quantifier (`no`, `none`, `never`, `every`, `all`, `only`, `always`, a superlative)
  carries the command that established it, or is rewritten to the bounded observation and the
  rewrite printed;
- every `run` command resolves (`command -v`, `test -x`, or the target exists).

`SELF-AUDIT · <n> citations re-read · <n> dropped · <n> quantifiers bounded`

## Posting (`--post`)

`gh` is on PATH and `origin` is GitHub, so posting is available. One review per head:

1. Check for an existing review at this `commit_id` first; never duplicate.
2. Body, in this order and nothing else: the verdict and its lines; `VERIFY BY HAND` whole;
   `FINDINGS OUTSIDE THE DIFF` (only findings with no line to anchor on; omit the heading when
   none); then one collapsed `<details><summary>Panel record: <n> claims · <n> attacks ·
   <n> dropped</summary>` holding `CLAIMS`, `ATTACKS TRIED`, `CONSIDERED AND DROPPED`, `LEDGER`
   and the `SELF-AUDIT` line.
3. An anchored finding lives in its inline comment only (RIGHT side, a line the diff adds).
4. **Never `APPROVE`.** Approval is a person's call.
5. This repo has one owner who authors most PRs. When the review account is the PR author, GitHub
   rejects `REQUEST_CHANGES` with a 422 and the whole call fails: post `COMMENT` and say in the
   body that the downgrade is the API's rule, not the verdict's.

Blocks 4–8 are terminal-only except inside the collapsed record.
